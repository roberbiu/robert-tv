# 优质来源接入调研（2026-10-29）

本轮只读公开资料和静态响应；未执行外部 JAR/JS/Python，未登录、未读取用户 Cookie、未操作生产目录。网站 GET 和目录可读不等于可播，更不等于无广告。

## 结论

饭太硬是聚合配置，玩偶哥哥是其中一个子站。把两者当成与量子/非凡同结构的独立 CMS 接口直接添加，会接错层。用户观察到片中博彩广告是真实质量缺陷，首版选择普通 CMS 主要方便接入，不能据此称优质源。

目前可以建立“准入候选”，不能把任何新候选直接宣称为已经无广告验收的默认来源。第一批最小适配试点选动漫巴士；玩偶哥哥作为核心第二批，连同扫码会话、转存和安全边界一起实现。饭太硬整仓不直接执行，逐站接入可审查适配器。

## 饭太硬一手响应

- 主入口：http://www.饭太硬.cc/tv 。普通浏览器 UA 返回标题“饭太硬 | 导航”，页面自己提供同 URL 为主接口，备用 fty.xxooo.cf/tv 和 gitlink 的 in.bmp。
- 同 URL 使用 okhttp/3.12.11：HTTP200，Content-Type=image/x-ms-bmp，实际文件头是 JFIF；本次响应 20,063 字节。静态提取最后一个 ** 后的 Base64，再仅解析 UTF-8 JSON，得到 13,238 字节 JSON。
- 49 个 sites 全部 type=3；配置包括 csp_WoGGGuard（玩偶哥哥）、NewCzGuard（厂长）、LibvioGuard（立播）、Dm84Guard（动漫巴士）、BiliGuard 等。玩偶使用 Cloud-drive 扩展参数。
- spider 指向 meitudata.com 的伪 jpg URL，带 MD5 值；MD5 不是发布者签名，也没有证明二进制与已审源码对应。本轮不下载执行它。
- 配置自己包含“请勿信视频中任何广告”提示，不能将热门/标注不卡/4K 当成无片中广告证明。
- 该配置直接引用 https://github.com/fantaiying7/EXT ，可静态看 JS/JSON；该库未发现 LICENSE 或对应 Guard Java 源码。因此不具备整仓直接纳入本项目并公开分发的已核验来源/许可链。

## 当前站点与域名陷阱

- 旧镜像写 https://www.wogg.com 。本轮 GET 得到德文 Wix 网页，不能当作玩偶站。域名名称相似、历史镜像存在不等于当前身份正确。
- 维护者配置 https://github.com/mymine/CatVodSpider/blob/main/json/index.json 列出 woggpan.888484.xyz、www.wogg.net 等；本轮前两者 HTTP200，均标题“玩偶哥哥共享站 维护中...”。可作为维护入口线索，不当可播验收。
- https://dm84.tv/ HTTP200，标题“动漫巴士-最新好看的动漫免费在线观看”，与适配器目标一致；未进入影片播放验证。
- 旧源码默认 www.libvio.link 已返回 Domain Suspended；维护配置的 www.libvio.app 是新式动态发布页，其 HTML 不是老适配器预期“可用”静态链接。饭太硬配置给的 www.libvio.pw 本次403。这说明不能照搬旧选择器/默认域名。
- 维护配置中的 www.czzy.site HTTP200，标题“厂长资源官网”，静态提供 cz01.tv、4kcz.com 等；旧默认 czys.pro 本机 TLS 失败。未访问媒体验证。
- ddys.info 本次返回标题“低调影视”，会员登录指向 ddys.app；旧 ddys.pro 本机 TLS 失败。与“低端影视”是否仍为同维护身份尚需核查，暂不自动默认。

## 扫码接入实际复杂度与直接搬运风险

参考源码 QuarkApi、UCApi 已含二维码UI/取码/轮询，不必从零构思扫码流程；但不能直接移植原样进入用户网盘。

- Cloud 接收 Quark cookie、UC uccookie、Ali token。Quark/UC调用各自 clouddrive API，包含 share/sharepage/save，再请求 file/v2/play 或 file/download；已存在转存行为，不能承诺完全只读。
- Quark扫码端点在 uop.quark.cn，UC在 api.open.uc.cn；应逐请求核实最终凭据流向和失效行为，不经过任意订阅作者的令牌交换服务。
- 参考实现会寻找名为 TV 的既存网盘目录并 clearSaveDir()/clean()。必须替换为本app独占目录与精确自建文件ID管理，不能清理用户原有目录。
- Quark参考实现存在ServiceTicket日志和可能以Cookie内容构造异常的分支；必须脱敏/禁止发布输出，并将会话放应用私有存储。不可共享或内置别人Cookie。
- UI依赖 Init.getActivity/Init.execute、QRCode、AlertDialog；还依赖Cache/User/Item/ShareData、Proxy/ProxyVideo、OkHttp/OkResult与工具类。构建使用Java11并用List.of/Map.of等，不能不审查就塞进现有Java8/min19工程。

## 最小扩展方案

1. 保留CMS适配器和受控更新；新增本地AdapterRegistry，仅允许已编入签名APK的adapterId，不放开spider/JAR/JS URL任意执行。
2. 受控目录允许adapterId、已审核站点地址/发布页、启停/分类/授权标签等数据；逐适配器字段白名单。作者新域名需有明确溯源，不能因包含“玩偶哥哥”文案就认定可信。
3. 先接独立HTML适配器（Dm84试点），再接站点直连分支；独立CloudSession/扫码页/转存服务与播放代理，处理Quark/UC/Ali。
4. 来源质量记录与适配器分开：广告未知/观察到片中广告/样本未观察到，记录日期、样本、字幕证据、实际起播与持续时长；不可写“永久无广告”。现有CMS降为后备，不继续增加同型广告CMS凑数量。
5. 验证覆盖：同名年份季集正确、搜索/分页/分类、遥控焦点、无认证也能浏览、扫码后重启保留/过期恢复、清晰度与中文实际证据、30秒/数分钟起播与拖动、换源回退、网盘写入范围与绝无凭据日志。账户动作只在用户授权后的正式接入试用发生。
