# 下一版导航与优质来源改造方案

日期：2026-10-29。用户已选择 B 版双猫电视徽章。此文记录调研后形成的实施方案，**不表示固定导航、热播或新来源已经开发、接入或实播验收**。本轮已实现的代码仅为名称、图标与 TV 横幅切换。

## 产品结构

一级固定顺序：**首页、热播、电视剧、电影、综艺、动漫、韩剧、美剧、英剧、日剧**。不继续暴露站点各自零散、顺序不同的分类为一级导航。

| 入口 | 内容与交互 |
| --- | --- |
| 首页 | 最近观看与搜索，保留既有历史与续播 |
| 热播 | 二级为电视剧、电影、综艺、动漫、短剧；显示来源、指标原名、统计周期和更新时间；点击以作品身份搜索可播放版本 |
| 电视剧 / 电影 / 综艺 / 动漫 | 各自汇合当前来源已准入的叶子分类，保留可靠地区、年份筛选 |
| 韩剧 / 美剧 / 英剧 / 日剧 | 实质为四个地区专区；二级均为电视剧、电影、综艺、动漫。按国家元数据匹配，合拍片标完整地区，缺地区不猜测 |

榜单负责发现作品，播放来源负责搜索和播放。排行不绑定某个视频站，避免换源后导航与热门作品一起变化。

## 热播调研结论

- [云合](https://www.enlightent.cn/analytics/top/tvranking)的正片有效播放与同品类市占最接近用户所说的国内近期播放率，产品也涵盖所需类型。但本轮网页只有空表与注册/小程序提示，未获得可直接接入的实际排行或公开稳定 API。
- [猫眼](https://piaofang.maoyan.com/web-heat)无登录公开响应可见30条节目与热度，所见品类为剧、综艺、网络电影，不能据此宣布动漫、短剧已覆盖；它是热度，不是全国播放市占。
- [骨朵](https://d2.guduomedia.com/)公开响应有前20热度，可作剧综/网络电影/国漫参考，短剧未核实。[爱奇艺](https://www.iqiyi.com/ranks1PCW/home)是单平台热度。
- 未核实到一个同时覆盖五品类、稳定公开、无需账户且有明确数据复用边界的接口。公开可读、开放 API、允许再分发是不同事实；不得绕过登录、验证码或付费获取。

实施使用独立 `TrendingRepository` 和按来源划分的适配器，保留真实来源、周期与抓取时间。失败保留最近成功缓存并显示日期。无可靠数据不填假榜，不将站点累计点击或人工片单包装为全国实时播放率；缺少某类时明确该类尚无榜单。数据入口确定前不把热播完成状态写进发布说明。

详见[排行与分类调研](research/navigation-trending-2026-10-29.md)。

## 固定分类的最小实现

1. 新增纯分类策略 `BrowseCategoryPolicy`：按每个 source 的真实名称和叶子 ID 映射统一类型，禁止跨源套同一 ID。
2. 浏览分页为每个 `(sourceKey, leafId, country)` 独立维护游标，有限并发、超时、去重；不扫描全库补齐列表。
3. 量子/非凡可使用已抽样验证的 `area` 缩小候选，但仍复核 `Movie.Video.area` 与类型。暴风本轮忽略地区条件，不能直接参加可信地区浏览。
4. 现有服务的父分类请求返回空、逗号拼 ID 返回全库均已实测；不能用这两种捷径实现四大分类。合拍国家按完整 token 匹配，缺失和错误数据不进入某国专区。
5. 验证重点是地区/类型正确、分页不重复、不混库、遥控焦点和回到首页；不以标签已显示作为分类实现完成。

## 为什么上一版没有饭太硬与玩偶

上一版把快速交付限制为普通 type 1 CMS，因此绕开了适配器与网盘链路，但没有完成足够的广告体验验收。这属于工程范围和质量评估不足，不是认定普通 CMS 比热门来源更优质。

本次对[饭太硬维护入口](http://www.饭太硬.cc/tv)仅做静态解包：49个站点均为 type 3，玩偶哥哥是其中的一个子站，依赖专用适配器和云盘参数。不能将聚合地址作为另一个普通 CMS URL 加入目录。配置自身也有广告提醒，不能因为热门而承诺无广告。

旧镜像的 wogg.com 当前为其他德文网站；维护配置里的玩偶入口本次为“维护中”。旧域名与镜像不能当当前可用性证明。

## 来源扩展顺序

| 批次 | 工作 | 准入条件 |
| --- | --- | --- |
| 先行 | 动漫巴士独立适配；更新厂长/立播的站点发现与直连分支 | 确认当前站点身份、源码依赖/许可，实测搜索、起播、拖动、字幕、片中广告、失败回退 |
| 核心 | 玩偶哥哥 + 夸克/UC 扫码、会话、转存和播放代理 | 站点恢复且链路可用；扫码仅在所选版本需要时出现；重启保留有效会话，过期可重扫 |
| 后续 | Bili等有明确实现和用途的补充来源 | 单独验收账号、画质、签名/代理与内容范围，不使用公共 Cookie |

参考实现见 [mymine/CatVodSpider](https://github.com/mymine/CatVodSpider)。其根 MIT 许可可读，但仍需逐文件核查继承链和保留声明，不能把旧 fork 的适配器更新时间当当前可用性证明。饭太硬的 Guard 二进制与可读源码未建立对应，不整仓直接加载。

新增本地 `AdapterRegistry`，目录只引用 APK 已编入的适配器及已审核参数。适配代码随签名 APK，在线目录只更新地址、启停和数据，不要求用户导入订阅。

云盘参考代码有清理既有 `TV` 文件夹、转存及凭据日志行为。正式移植必须使用应用独占目录，仅操作本应用创建的精确文件 ID；会话保存在私有存储，发布日志脱敏。不得直接复制这些清理逻辑后连接用户账号。

普通 CMS 保留为后备；新的优先来源必须有真实样本，不继续靠数量、HTTP200或清单可达称“优质”。质量标签区分“广告未知 / 观察到片中广告 / 样本未观察到广告”，记录日期和样本，不承诺永久无广告。

详见[来源与扫码调研](research/sources-2026-10-29.md)。

## 交付顺序与验收边界

名称与已选 B 资产 → 固定导航与可信分类 → 独立站点适配及广告样本 → 玩偶与安全扫码链路 → 可靠榜单接入 → 同签名打包、模拟器与雷鸟试装。

以上后续模块仍需实施，不把本轮品牌编译通过称为全部新功能通过；不购买数据服务、不运行未经审查的外部适配程序，也不操作用户现有网盘文件。
