## 组件职责

| 组件 | 职责 |
| --- | --- |
| 电视交互层 | 首页、搜索、详情、选集、版本选择、授权提示和遥控焦点 |
| 搜索与版本协调 | 多源查询、超时隔离、同片同季集匹配、均衡排序和失败替代 |
| 来源管理 | 内置目录初始化、准入校验、按需更新、健康状态、最近可用配置回退 |
| 已准入适配器 | 将特定来源转换为统一搜索、详情、播放与字幕信息 |
| 播放与字幕层 | 复用播放器，控制播放、选轨、字幕加载和失败信号 |
| 本机状态 | 保存有效会话、配置、观看历史和播放进度，避免无关上传 |
| 项目维护目录 | 外部静态目录，更新来源地址、启停等参数；不是家庭自部署服务 |
| 外部内容与认证服务 | 提供实际内容、视频、字幕和必要的账号授权 |

主要链路为：遥控操作 → 浏览或搜索 → 聚合结果与版本选择 → 实际起播 → 字幕优选；失败时回到同片同季集候选。来源更新独立于该链路，失败不得阻断已有可用功能。

## 单 APK 与来源更新边界

1. APK 内置初始目录及必要适配器，不以成功下载配置作为进入首页和搜索的前置条件。
2. 默认目录仅引用已准入的适配器。优先普通 HTTP JSON/XML 与来源、许可明确且可审查的适配逻辑。
3. 在线目录只更新允许的地址、启停、排序等数据，先验证再替换，保留内置与最近可用版本。
4. 不直接执行第三方订阅所指向的未知 JAR、JS 或 Python。首版适配代码变化随签名 APK 发布。
5. 若未来必须热更新可执行适配器，需作为单独方案评估审核、固定版本和签名准入，不能直接追踪第三方“最新 JAR”。
6. 启动和搜索时按需维护，不要求电视待机时持续运行采集任务。

公开订阅中经常包含执行依赖，因此“能导入 JSON”不等于“只更新数据”。保持上述边界会限制可直接接入的来源数量；是否满足内容需求必须通过片单实测，不能预先把第三方目录全部视为可用。

## 中文字幕和版本选择

首版路径：同片中文版本优选 → 内封中文轨优选 → 来源附带外挂字幕 → 尝试其他同片同季集版本 → 最终仍无中文时标注并允许播放。

区分检测确认、来源标注与未知。外部字幕匹配需核对年份、季集和版本；不同剪辑版本不保证自动同步。换源后只有时间线可匹配时才恢复进度。

默认采用均衡选择并展示可确认的清晰度、字幕和授权要求，不强制把最高分辨率视为最佳体验。未知画质、未知字幕不得伪造为已检测结果。

上游已有 [ASSRT 网页字幕检索](https://github.com/q215613905/TVBoxOS/blob/ab11d289e09963a9daf65ca7f6b7a9a8cbe184e1/app/src/main/java/com/github/tvbox/osc/viewmodel/SubtitleViewModel.java)，但依赖网页结构且本轮未实测。正式 API 的凭据、额度与可持续接入方式未落实前，不将其作为基础体验的唯一依赖，不在公开 APK 中硬编码私人 token。相关服务只作为后续增强评估。

## 账号与外部依赖

无需认证的内容不被登录页阻断；只有选中的来源确实需要认证时才触发扫码。认证按适配器独立验证，记录令牌实际流向、是否需转存和会话失效恢复行为，不照搬未经审查的第三方令牌交换流程。

无需家庭服务器仍意味着存在内容服务、静态目录与可选认证服务等外部依赖。首版不引入常驻计算后端或付费字幕服务；任何新增服务的维护责任和费用应明确说明。来源适配、片单回归和 APK 发布需要持续维护，不承诺永久免费或永久可用。

## 直播、升级与隐私

直播优先复用上游入口和普通播放列表；只有默认频道与遥控切台验证成本较低时纳入，否则隐藏入口，不另建直播系统。

保留项目独立且稳定的发布签名，后续升级使用同一签名。私钥、密码、Cookie、token、带凭据的 URL 与个人观看记录不得入库；日志、问题反馈及测试记录需脱敏。

## 验证门槛

M0 先验证基线可构建和单包安装；不能构建时先修复或重新评估基座，不继续堆叠业务。默认来源无法形成满足验收片单的可用组合时，应回到来源与方案评估，不能仅凭界面完成就宣布可交付。

模拟器或其他测试设备成功不等于雷鸟真机验收通过。具体里程碑、记录格式和交付要求见[开发文档](development.md)。
