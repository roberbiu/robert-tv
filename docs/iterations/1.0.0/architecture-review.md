# 榴榴芙芙影视 1.0.0 独立架构审校

日期：2026-10-29（北京时间）。审校角色：独立架构审校 agent，与主架构编写角色分离。

## 1. 结论与适用边界

**结论：通过，可进入阶段3开发。没有尚未满足的阶段2阻断条件。**

该判定针对当前选定的“应用内可审查玩偶适配＋应用自管夸克/UC会话与文件服务＋来源快照共存＋真实五品类热度元数据”开发设计。它不是1.0.0正式发布验收，也不批准将尚未充分审查的饭太硬共享Guard直接加载到真实账号或正式包。

阶段3仍须实施并取得已确认的真实账号、最终候选APK、真机、片单、媒体质量、连续播放及跨日观察证据。以下列出的开发与发布检查是已确认门槛，不是以待补外部依赖换取的“附条件放行”。若实现中发现某个已确认P0实际不可达，须带证据和替代方案回用户，不能静默改范围。

## 4. 审校期间已消除的歧义

1. **旧榜不能靠新GET续命**：已知源数据日期优先决定新鲜度；未知日期使用内容指纹及首次观察/变化时间，获取时刻不能冒充官方更新；加入“刚获取但榜已旧”等夹具。
2. **电影主榜的时间合同**：已改用有数据日期与DAILY周期的骨朵网络电影主子榜；百度没有源更新时间，不单独承担主榜验收，且网络电影范围必须显式标注。
3. **补充来源不留整项空白**：Dm84作为具体实现首候选，有当前首页56卡、分类36卡及一次成功搜索3卡；搜索超时样本保留。厂长只是需补合同的备用，不默认可用；解析/质量/许可失败则停止准入，不能拿旧CMS或名称凑N。
4. **宿主路由无默认兜底**：补齐默认拒绝、media/proxy/proxyM3u8/dash统一租约、配对POST及Host/Origin/CORS边界，避免只关闭文件写接口却留下媒体/缓存读取旁路。
5. **合法凭据轮换不打断播放**：sessionGeneration明确为授权epoch，正常同账号轮换单独更新credentialRevision；旧凭据晚到失败不得覆盖更新后的会话。
6. **自动预览不隐式发起扫码**：现DetailActivity会自动jumpToPlay，方案已区分播放意图，自动预览/字幕替代只展示授权选择，不强弹二维码或停止仍可用原版本。
7. **聚合叶子公平调度**：保存轮转起点，避免固定前几个叶子永久吃满一页；A批需冻结总请求/耗时预算并使用慢源/空页夹具验证。

## 5. 进入开发后的必做检查

这些项目不能从本审校推导为已通过：

- 本人扫码后Quark/UC服务端当前兼容、权益、分享/季集正确性、实际媒体、字幕、声音、拖动和片中广告；不支持provider不能冒充可播。
- 私有加密的具体平台参数、API19与23+分支运行、损坏/密钥丢失及正常升级；不得为兼容放宽TLS或改为共享/明文凭据。
- 凭据更新、取消、退出/换账号与并发代理；精确文件账本、超时未知结果和清理归属；无租约、越界路径、配置/cache写入口均应拒绝。
- 固定导航/国家×类型覆盖、当前热榜字段和日期、榜单到统一搜索的作品身份；复制源ID直接当播放站ID或把数据日冒作更新时刻均不可接受。
- Dm84 iframe到真实媒体的解析及质量；元数据成功不代表无广告或优质直连，只有实际样本通过后才可加入正式优先名单。
- 固定20部片单至少16部正确候选；同片单12部各至少3分钟；玩偶60分钟；至少24小时正常跨日观察；最终APK真机及声明设备、新安装和覆盖升级分别留证据。preview.2没有的网盘会话记不适用，不伪造迁移。
- 正式APK、签名、版本、源码、哈希、来源/许可和支持范围一致；有P0缺口不创建正式标签、不以预览记录或新增单测数量代替发布验收。
