状态：**草案 v1，待用户确认**。日期：2026-10-29（北京时间）。

本文是阶段1的产品需求文档，不是技术选型、开发完成报告或正式发布声明。目标版本为用户指定的 **1.0.0 正式版**，用于本人及朋友安装使用。当前已发布的 preview.2、后续源码修复和本轮需求草案应分别记录，不将预览证据自动认定为正式版通过。

## 2. 产品目标与用户

目标体验：**安装一个 APK → 直接浏览或搜索 → 选择版本观看 → 下次方便继续看**。软件处理默认来源、失效和必要更新；用户不承担寻找接口、导入源、手填 Cookie 或维护家庭服务的工作。

- 主要用户：雷鸟鹤6 Ultra 的拥有者，使用电视遥控器观看电影、电视剧、综艺、动漫、纪录片等内容。
- 新增受众：收到安装包的朋友。每位使用者在自己的电视上独立安装，确有需要时登录自己的网盘账号，不依赖开发者或其他人的登录态。
- 1.0.0面向小范围分享安装；应用商店上线、商业收费、统一注册系统、云端同步个人历史不在本轮范围。
- 支持设备以正式验收清单为准。朋友的电视型号尚未提供，不据此承诺“所有Android电视通用”。

原始目标继续有效：单APK、开箱即用、无需用户配置来源或服务器、遥控可用、广泛点播、多源搜索与失败替代、中文字幕优先及缺失降级、均衡选版、必要扫码且尽量保持会话、历史续播。

## 5. 核心使用流程

1. **朋友首次安装**：取得同一正式APK → 安装 → 看到“榴榴芙芙影视”与中文首页 → 无历史时可直接搜索/浏览 → 选择免认证版本观看。整个过程不获取开发者配置，不继承其他人的账号。
2. **从热播找片**：进入热播 → 选择品类 → 看清榜单来源、指标及日期 → 选择作品 → 统一查询版本 → 查看画质、字幕和授权信息 → 观看。榜单没有数据时不能伪造结果，也不能悄悄变成普通站点推荐。
3. **首次使用玩偶网盘版本**：搜索/浏览作品 → 选择需要授权的版本 → 明确哪种网盘需要扫码 → 用户手机授权 → 成功后播放。取消或失败时可返回、重试或选择免认证版本，不被迫登录另一种网盘。
4. **再次观看与会话恢复**：再次打开/重启/正常升级 → 首页显示自己的最近观看 → 有效会话直接复用 → 继续观看。服务端确认失效才进入重新扫码流程，历史保留。
5. **换源与异常**：某来源超时或不可播 → 其他来源继续可用 → 软件尝试合适替代并允许手动选择 → 替代也失败时明确原因和下一步，不误切作品/集数，不丢失原有可用播放状态。

## 6. 状态与降级要求

| 情况 | 面向用户的行为 | 不可接受的处理 |
| --- | --- | --- |
| 新增来源配置或插件不可用 | 说明相关来源暂不可用，旧来源仍可浏览/搜索；保留最近可用状态并允许重试 | 启动整应用失败，要求用户自己找接口 |
| 未登录/扫码取消 | 仅所选需要账号的线路提示授权，可返回选择其他版本 | 全局登录墙、强制把夸克和UC全部登录 |
| 网络超时 | 网络状态提示、重试/换源/返回，不误清有效会话 | 直接判定账号失效并要求反复扫码 |
| 会话真实失效 | 保留历史，明确哪个网盘需重新授权 | 静默丢失记录、要求手工复制Cookie |
| 中文字幕不足或未知 | 尝试匹配版本，显示真实证据与未知，仍允许用户播放 | 冒充已确认中文、因无文字轨误判所有硬字幕 |
| 地区/类型字段缺失或不匹配 | 不猜国籍、不混库；无匹配时中文空态 | 把欧美都归美剧，或空页后回填全库 |
| 热播数据暂时失败 | 有有效历史数据时显示日期及过期状态，无数据时显示明确空态 | 将缓存冒充实时、以五个空态作为热播交付完成 |
| 云盘临时文件需处理 | 只处理播放所需、由本应用明确管理的文件范围 | 清理用户原有目录、公开个人文件/凭据 |

短期外部故障允许有诚实降级；**P0能力在正式验收时没有成功证据，仍属于未完成**，不能用降级页面永久替代所需功能。

| 建议门槛 | 建议验收方式 |

| 声明支持的设备可实装 | 至少1台雷鸟鹤6 Ultra真机，建议另加1台不同型号Android TV/盒子；只有已验证机型才列为实测支持。暂时无法取得第二台时，带有限设备范围方案回用户，不能自动宣传全机型兼容 |

| 同一片单实播短检至少12部，每部观察≥3分钟 | 从上述固定20部片单选取，不另挑易成功作品；剧、电影、综艺、动漫、纪录片、短剧各建议≥2部，地区可交叉覆盖；每部检查实际画面、可听声音、字幕状态、一次拖动及拖动后继续播放。未找到/失败不计作实播通过，保留完整结果 |
| 主力玩偶线路连续播放≥60分钟 | 固定1部具有代表性的作品，记录起播、持续进度、声音、暂停/继续、拖动及返回；不能只看URL/HLS/第一帧就判定稳定 |
| 会话跨日观察≥24小时 | 记录同一测试账号首次扫码、关闭/重启及跨日再次播放；服务端会话仍有效时必须复用，真实提前失效时验证重新扫码恢复；只进行正常使用，不持续保活。72小时可作加强观察。此为观察窗口，不要求平台保证24小时有效；如频繁重扫影响正常观看，须如实报告并带回用户，不能以“平台原因”直接免验 |
| 字幕与替代包含成功、失败样本 | 验证已确认中文、仅来源声明、未知/无中文；覆盖替代成功及替代失败回退、用户手动换版/换集，不误串作品 |
| 共存与故障注入 | 使新增来源或授权链路不可用，确认现有免认证来源及首页仍能工作；故障源不无限占住查询/播放，用户能取消或返回 |
| 升级与独立用户数据 | preview.2升级验证既有历史/续播；具备扫码能力的同签名候选包升级验证仍有效的会话，preview.2无会话标不适用；不同安装/使用者之间无凭据和历史混入；交付包中没有测试账号、测试媒体或个人数据 |
| 正式发布缺陷门槛 | P0需求全部有通过证据；无阻断安装/观看、数据丢失、凭据泄露或错误文件操作问题；其他已知限制逐条记录，影响已确认范围时由用户决定是否接受 |

对搜索等待、起播时长、弱网、长时间内存/崩溃等质量项，阶段2应制定可重复的测试条件和判据，明确设备与网络，不承诺任意网络下固定秒数。不能以“单元测试数量增加”替代使用体验验证。

正式版验收时使用人员各自授权的账号；不要求用户分享密码、Cookie或个人网盘文件作为新前提。若测试需用户在手机上完成扫码或在家中电视执行步骤，应在阶段3提供具体、短小、可复核的操作清单。

阶段3先提供“待验收候选包”用于上述安装、升级和真机验证；通过后才进入正式交付及朋友分享。最终交付二进制必须能对应验收证据；若验收后重新构建或修改，应重新核验包一致性并补测受影响项目。

## 9. 本阶段需要用户确认的事项

1. **热播口径**：建议优先接受“有明确来源、周期、更新时间的真实热度参考”，不称全国播放率；若坚持正片有效播放/市占，阶段2须先落实对应数据入口与使用条件。两种口径都不能用站点点击、人工片单或五个空页冒充五品类热播。
2. **来源交付边界（纳入整份文档确认，不重新询问已明确偏好）**：将“现有来源 + 实际可用玩偶 + 经审核实播的补充站点”共存作为1.0.0发布范围；不要求饭太硬49站全开，N以阶段2准入名单为准。玩偶不得静默延后，饭太硬精选接入与独立Wogg方式由架构依据验证比较后选择。
3. **正式验收范围及建议值**：确认第7节的设备、20部片单中至少16部有正确候选、同片单12部各观察≥3分钟、玩偶60分钟、会话跨日观察24小时等建议，或明确需要调整的范围。具体片名和朋友设备可在阶段2/3冻结验收表时补充，无需现在提交账号或文件。

以上三项与整份文档由用户最终确认。若不接受某项，产品 agent 应修订并保留版本记录，不将未答复等同同意。品牌B、应用名称、十项导航和玩偶优先等已明确事实不重复征求偏好。

## 10. 阶段2交接要求

架构师只在用户确认本稿后开始本轮方案。应逐项映射V100需求，给出实现边界、依赖、故障与回退、会话/文件操作范围、来源名单和质量证据计划、数据来源与发布兼容范围，再由独立审校判断可行性。
