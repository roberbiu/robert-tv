计数规则：

1. 片单分母固定为 v1 的 20 行。正确候选、短检通过分别按**不同 sample_id**去重计数，同一作品多来源或多次重试不能多算。短检通过必须属于同表且身份正确，不能另选易播作品凑 12 部。
2. 标题命中、HTTP 200、可读列表、解析出媒体地址、HLS 可访问、第一帧、编译通过和单元测试通过，均不等于正确候选或实播通过。
3. 候选身份须核对片名、发行/所属年份、季、集/期或正片、地区和类型，并与实际选中版本一致。`请回答1988` 的标题数字不能当发行年；`流浪地球2` 的续作号不能当季号。未知字段保持未知，不自动判一致。
4. 两部短剧的发行年和地区在冻结时未核实，CSV 记 `unknown`。执行前人工核验可获得的公开作品信息、来源条目和实际文件/画面身份，记录证据与不足；确实未提供的年份不得猜填。仍不能排除同名/错季集时记待确认，不能计正确或短检通过。
5. 观察时长是实际观察，不是把播放头拖到“三分钟”。字幕记录可为检测确认、来源声明、硬字幕画面、未知或确实缺失；不要求每条必有中文，不把无文字轨当无硬字幕。广告如实观察，不凭短检承诺永久无广告；大量片中广告与默认优先来源准入分开判断。
6. 等待、起播、失败时长和网络条件据实记录。本模板不新增任意网络下固定起播秒数、无广告、4K、72 小时、全平台账号或所有电视兼容等门槛。

## 4. CSV 填写与逐部执行

`validation-samples.csv` 每行保存一个固定样本及其当前执行汇总。运行前所有观察、设备、文件、账号权益和证据字段均为“未执行”，不是空白通过。重试另存按 sample_id/轮次关联的脱敏证据，并保留前次结果，不覆盖失败经过。

1. 先填写候选 APK 哈希、设备代号、北京时间、网络条件和测试人员代号。使用最终候选，不混填旧包结果。
2. 手动搜索/从榜单或分类进入，记录启用来源、搜索结果、实际片名/年份/季/地区/类型及核对结论。身份不足单列待确认；错误候选不能进入通过计数。
3. 用户主动选定来源/网盘线路，按需由本人扫码。记录“免认证/夸克/UC”、权益观察和提示类型，不能把权益不足、网络超时、二维码过期、媒体过期都记成会话失效。
4. 核对实际选中文件的作品、年份、季集/期或正片，记录去除私人目录和标识后的文件身份摘要；再观察画面/真实时间推进、可听声音、字幕、画质、片中广告、一次拖动及拖动后继续。
5. 记录实际观察秒数、各项状态、错误及恢复、返回后的历史/续播；据事实填写“正确候选/身份待确认/错误/无候选”“短检通过/失败/取消/未执行”等结论。遇到真实不足不能填不适用来跳过。

CSV 中“清晰度”分别记录来源标注与实际可观察分辨率/解码器信息；未知时写未知，不以标题 4K 当真实画质。“声音”须实际可听，不以音轨存在替代。“字幕”须明确证据类别与中文状态；硬字幕可用画面证据，不能据轨道缺失误报无中文。

公开记录只使用来源目录 ID、作品公开身份和测试代号。**不记录私人媒体/分享/签名 URL、Cookie、token、ServiceTicket、扫码票据/二维码、提取码、账号标识、个人历史内容、完整网盘路径或私人文件 ID。** 需要留图/日志时先遮蔽凭据和个人信息，证据栏只放脱敏文件相对路径和必要校验摘要。不得要求测试人员把账号凭据提交到公共仓库。
