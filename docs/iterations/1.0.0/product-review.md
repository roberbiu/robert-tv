# 1.0.0 产品需求审校记录

日期：2026-10-29。对象：[产品需求草案v1](product-requirements.md)。本记录仅为阶段1产品审校，不是架构可行性评审、开发验收或用户批准。

## 审校角色与结论

| 角色 | 审查范围 | 结论 |
| --- | --- | --- |
| 产品经理agent | 汇总原始需求、后续反馈、1.0.0范围与确认项 | 形成草案，提交用户确认 |
| 独立产品需求审校agent | 原始目标、玩偶优先、五品类热播、共存、登录、阶段门槛与需求覆盖 | 无阻断性范围遗漏；完成消歧义修订后可交用户确认 |
| 正式交付与使用体验审校agent | 朋友全新安装、实际设备、独立账号、升级、真实观看和发布证据 | 范围合理；完成升级与失败恢复判据澄清后可交用户确认 |

## 审校要求的修订

1. V100-06／09：五品类真实热播与实际玩偶链路属于建议P0，空页或仅有名称不能算完成，其他来源不能代替玩偶优先。
2. 会话观察：24小时是跨日观察窗口，服务端仍有效时应复用，提前真实失效时验证重新扫码恢复；不承诺固定登录有效期。
3. 固定片单：区分身份正确的版本候选与真实可播放；实播样本从同一固定片单选取，保留失败记录，地区/类型长期缺口不能永久用空态算完成。所有数字仍是待用户确认的产品建议。
4. V100-19：preview.2无网盘会话，不能伪称旧会话迁移通过；历史/续播和网盘会话的升级测试应使用各自具备该能力的基线。
5. V100-12：只有原先存在可用版本时才要求恢复；全部候选失败时提供明确失败、返回和重试，不能要求凭空恢复播放。
6. 发布顺序：先提供待验收候选包完成真机和声明设备验证，再标记正式并交付朋友安装使用。
7. 阶段边界：用户确认阶段1后才进入架构；架构方案独立审校可行后进入开发，不额外添加默认的人为审批轮次。实质性范围/成本/前提变化需回用户确认。
